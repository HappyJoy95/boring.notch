# Boring Notch 焦点活动与 Codex 置顶任务设计

日期：2026-10-03
状态：用户已确认
工作树：`/Users/ashui/vibe-coding/boring.notch.git`，分支 `codex/notch-three-level-activities`

## 1. 目标

让 Boring Notch 的刘海围绕内容生命周期显示三层活动：持续中的焦点活动占主位、Codex 状态变化短暂下弹、Codex 置顶任务的最新回复在展开菜单中只读查看。

## 2. 已确认需求

- 改造 Boring Notch App 本身。
- 焦点活动首期接入 QQ 音乐 macOS 客户端；导航是同类活动的后续来源，不纳入首期。
- Codex 只显示在 Codex 中已置顶的任务。
- Codex 状态变化作为临时活动，从刘海下方出现，稳定后回到焦点活动。
- 展开菜单自动显示每个 Codex 置顶任务的最新助手回复。
- Codex 内容只读；不从刘海发送消息、回答问题、处理审批。点击任务只负责返回 Codex。
- 不做全局 macOS 系统通知转移；常规通知横幅继续由 macOS 管理。

## 3. 活动层级

### 常驻焦点活动

- QQ 音乐播放期间复用当前 Now Playing / Music Live Activity 显示歌曲、歌手、封面和进度。
- 展开音乐面板时复用现有播放控件；QQ 客户端是否支持控制需实机验证。
- 暂停或没有曲目信息时恢复 Boring Notch 现有闲置展示。
- 导航等持续活动作为后续来源，本期不实现。

### 临时 Codex 活动

- 仅 Codex 置顶任务的状态变化可触发。
- 显示任务标题和短状态；不展示提示词、工具调用、命令、推理或 diff。
- 临时卡片短暂占据主位，安静 5 秒后恢复最新焦点活动。快速连续变化合并并重置计时；本期不增加单独设置项。
- 等待用户处理时只标明等待状态，不在刘海里提供操作。

### 展开菜单里的 Codex 置顶任务

- 展示所有当前置顶任务；取消置顶或归档后移除。
- 每项展示任务名、状态和最新一条助手回复；只读、可滚动，长回复截断显示。
- 不搬运会话历史、用户提示词、工具输出、命令或 reasoning。
- 点击后尝试打开对应 Codex 任务；不支持深链时打开 Codex 主窗口。

## 4. 建议架构

### QQ 音乐

优先复用 `NowPlayingController`、`MusicManager` 和现有 `MusicLiveActivity`。当前控制器监听 macOS MediaRemote，接收系统当前播放源元数据。QQ 音乐首要验证是能否发布歌曲、歌手、封面、进度及媒体控制命令；只有实机验证出现缺项，才实现 QQ 专属适配器。禁止读取 QQ 音乐私有账号文件、Cookie 或登录态。

### Codex 只读伴随组件

- 在 Codex 受信任插件中运行独立伴随进程：通过 Codex App Server 获取原生置顶分区及最近回合，通过官方 Lifecycle Hooks 上报运行、等待、结束、打断等状态。
- 本机 Codex CLI 的 `thread/list` 返回 `section.name == "Pinned"`，可据此过滤；`isPinned` 请求参数在本机版本上没有过滤效果，不能仅依赖它。
- `thread/turns/list` 的单回合结果包含 `agentMessage.text`。只选择最新回合的助手最终回复，排除用户消息、工具调用和其他项目；不恢复会话。
- Codex 伴随组件向 Boring Notch 本机回环连接推送精简数据。接入需由用户在 Codex 审核并信任插件 Hooks；不得绕过信任流程。
- 首先验证本机配对与回环通信。桥接只接收本地连接，使用短期配对凭证；运行期间只传任务 ID、标题、状态与最新回复；不上传、不记录日志、不持久化回复正文。取消置顶后清除对应内存数据。
- 状态事件仅通过 Hook 进入展示模型；Codex 卡片不注册任何写操作。

### 活动仲裁

以独立状态模型管理常驻焦点与临时事件。焦点活动作为基础层；Codex 状态事件在前台短暂显示；置顶任务及最新回复只在展开菜单出现。临时卡结束后读取最新音乐状态恢复展示，而非恢复过期快照。

## 5. 已考虑的实现路径

1. **首选：Codex 官方 App Server + 官方 Hooks + Boring Notch 的只读回环桥；音乐复用现有 Now Playing。** 用最小本机原型验证原生置顶分区、最新回复、Codex Hooks 和连接配对。
2. **复刻 Pinland 的完整同步、消息和审批。** 超出本期需要，不采用。
3. **读取 Pinland 私有内部协议或应用数据库。** 不采用；Pinland 插件仅作行为参考，不复制受限代码。

## 6. 隐私与故障行为

- Codex 回复正文只在展开菜单中本机显示，不写入日志或持久化缓存。
- Codex 断连时移除动态状态和回复，不显示陈旧内容；音乐活动继续可用。
- QQ 音乐未发布系统元数据时显示 Boring Notch 原有空闲 UI，不扫描私有数据。
- 不读取 Codex 凭据、不修改 Codex 会话，不接收全局系统通知。

## 7. 验收标准

- QQ 音乐播放时显示正确曲目信息；进度和控制能力分别验证。
- 未置顶 Codex 任务绝不出现在刘海活动或展开菜单中。
- 置顶任务状态变化可短暂下弹，5 秒安静期后恢复 QQ 音乐。
- 展开菜单自动更新每个置顶任务的最新助手回复，不混入提示词、历史消息或工具输出。
- 刘海中没有发送、继续、批准或拒绝等 Codex 写操作。
- 点选任务能返回对应 Codex；无法深链时打开 Codex 主窗口。
- Codex 断连不留陈旧卡片；现有 Boring Notch 行为继续可用。
- 不改 macOS 全局通知设置。

## 8. 技术验证结果与风险

- 本机 Codex App Server 只读查询返回 32 个线程，其中 2 个有原生 `Pinned` section；Codex 桌面侧只读列表也返回 2 个置顶任务，数量一致。`isPinned` 参数在本机 CLI 版本上未生效，因此以 `section.name == "Pinned"` 做兼容筛选，并保留版本差异检查。
- 最近回合 API 能返回助手回复字段；状态消息来源需要 Lifecycle Hooks，因为独立 App Server 对桌面线程报告 `notLoaded`。
- QQ 音乐 App 已安装（macOS 客户端 11.10.0），但当前没有运行；未验证真实播放源、元数据或控制行为。静态代码审阅不能替代实机播放验证。
- 本机有 Swift 6.2 与 Command Line Tools，但没有完整 Xcode，因此当前环境无法运行 `xcodebuild` 编译完整应用。纯 Swift/Node 逻辑可单独验证；最终 App 集成需完整 Xcode 环境。
- Codex 任务 URL 深链需要在本机验证；不支持时回退打开应用。
