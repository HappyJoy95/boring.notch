# 多来源任务接入

灵动岛通过 `AgentTaskProvider` 注册应用来源，当前注册 Codex、WorkBuddy、DSH 和 MiMo Desktop。MiMo 支持置顶会话及历史正文读取；安装接入组件并重启 MiMo 后支持发送、打断与运行状态同步，暂不提供精确跳转。

来源独立提供任务列表、历史分页、单任务刷新、发送、停止和能力声明。统一服务按来源分发操作，未注册来源不会回退到 Codex，也不会获得发送或中止能力。界面按能力显示输入区域；WorkBuddy 保留已有发送组件的安装、连接检查和不确定送达保护。

## 身份与兼容

Codex 保留已有裸会话 ID，确保持久已读记录兼容；其他来源使用 `来源:本地ID`。显式来源与 ID 前缀不一致的数据会被拒绝。任务选择、历史缓存、新增时间、提醒时间和已读记录均使用完整 ID，不同来源的同名会话及消息不会串联。

保留 `CodexPinnedTask`、`CodexDisplayStatus` 和现有 XPC 方法名称，减少对现有功能的改动；这些模型已作为所有来源的公共任务与状态契约。来源适配器负责把应用状态转换成 running、waiting、completed、interrupted、idle。

## 刷新与推送

各来源并发读取，共享同一次正在进行的刷新，并且只应用一次结果。每份列表校验来源与重复 ID；来源失败保留自身旧快照，成功返回空列表只清除自身任务。`failedSources` 记录部分失败，`lastRefreshFailed` 在任何来源失败时为 true。

Codex 推送只替换 Codex 的列表，同时更新统一服务和界面协调器，保留其他来源。刷新失败时以当时的最新状态回退，因此读取期间到达的推送不会因旧缓存而丢失。采用设置中的会话刷新间隔（默认 5 秒）；成功读取与实时推送的精确先后顺序需要未来来源接口提供序号或版本才能保证。

## 添加来源

1. 实现 `AgentTaskProvider`，声明来源 ID 和实际支持的能力。
2. 在 `CodexPinnedTasksService` 的默认来源列表中注册适配器。
3. 适配器返回规范化任务及公开消息，将应用内部状态映射到公共状态。历史按原接口分页，发送返回明确送达结果，不自动重试不确定操作。
4. 按应用实际支持添加来源名称、图标和打开会话入口；没有确认跳转协议的来源不生成链接。
5. 验证失败保留、空列表清除、相同 ID 隔离、未读恢复及操作分发。

## 验证

运行 `bash Tests/AgentProviders/run.sh`。覆盖三来源分发、未知来源拒绝、来源冲突、重复列表拒绝、部分失败、推送合并、刷新复用、历史隔离、未读持久化及已有任务模型回归。

另运行 Codex 状态、停止 IPC、WorkBuddy 消息与发送组件回归，并执行 macOS Debug 编译。服务级测试使用隔离的偏好存储和模拟来源，不读取真实对话、不向应用发送消息。真实界面、提醒和应用间交互仍需运行验证。
