# WorkBuddy 接入

Agent 页同时展示 Codex 和 WorkBuddy 的置顶会话，卡片显示来源名称。WorkBuddy 数据仅来自当前账号的本地置顶列表、只读会话数据库以及公开对话记录，不读取凭证、推理或工具输出，只读接入不修改 WorkBuddy 配置。发送功能另行安装我们自己的扩展。

支持查看标题和状态、历史分页、置顶变化提示音以及新完成回复的未读提醒。在灵动岛中打开详情后清除其未读标记。重启保留灵动岛自身的已读状态；首次接入不为已有完成回复弹出提醒。

详情支持向当前置顶 WorkBuddy 会话直接发送消息。发送通过随应用分发的独立 `boring-notch-bridge` 扩展完成，源码位于 `Integrations/workbuddy/`，不读取、调用或替换 Pinland 扩展。仍保留 WorkBuddy 原生 `workbuddy://chat/<会话ID>` 入口；当前没有 WorkBuddy 中止按钮。

后台刷新间隔为 5 秒，实际延迟取决于读取时间。本地文件结构属于版本相关实现，更新 WorkBuddy 后可能需要适配。单页历史读取限制为 128 KiB，只显示最多 32 条用户/助手公开消息；更早内容继续分页读取。

验证：

- WorkBuddy 当前账号 3 个置顶会话读取成功，时间戳有效。
- 实际历史两页分别返回 7 和 2 条公开消息，页间没有重复 ID。
- 非法/非置顶会话历史请求被拒绝。
- Provider 解码、打开会话链接与不同应用的会话 ID/已读状态隔离测试通过。
- 未读逻辑回归和 macOS Debug 编译通过。

界面展示、打开 WorkBuddy 的实际跳转和真实运行完成后的提醒效果仍需运行验证。

## 消息展示清理

读取端在截断文本之前提取 user_query 中的真实请求，并移除已知的内部提醒、时间及项目上下文包装。仅含内部提醒的记录不显示；原始 WorkBuddy 文件不修改。正常助手回复保留。

消息清理回归测试、Provider 隔离测试及 macOS Debug 编译通过。本机三个置顶会话的当前历史页未再输出 memory_and_skills_reminder 或 additional_data 包装。运行中的旧版本需要重新启动新构建后才能看到变化；真实完成提醒及跳转仍需界面验证。

## 独立发送组件

新电脑需要先安装 WorkBuddy。在灵动岛打开一个 WorkBuddy 置顶会话，点击“安装 WorkBuddy 发送组件”，重启 WorkBuddy 后点击“重新连接”，即可出现输入框。组件源码随 XPC Helper 的资源打包，安装不依赖这台电脑已有的其他扩展，也不需要另外安装 Node.js。安装目录为 `~/.workbuddy/extensions/boring-notch-bridge`；已有目录不会被自动覆盖。

我们自己的扩展仅申请 `conversations.get` 和 `conversations.sendPrompt` 权限。它绑定本机回环地址，使用安装时独立生成的随机令牌；配置权限为 0600，不保存消息正文。发送前检查当前账号的置顶列表和有效会话；单条最多 12000 个 UTF-16 单元。界面区分已提交、已排队、失败和结果未知。结果未知不自动重发，需要到 WorkBuddy 核对。相同请求 ID 的回执写入本地，重启后不会再调用发送；最多保留 4096 个回执，达到限制后停止接收新发送。

组件设为常驻，避免 WorkBuddy 回收非驻留扩展。WorkBuddy 的内部扩展协议可能随版本变化；本机验证版本为 5.6.2。更新后若连接失败，仍可通过原生入口继续对话。

验证范围：桥接回归与独立进程 HTTP/IPC 联调共 7 项通过，包括权限拒绝、中文多行文本、排队回执、重复请求以及重启后的回执恢复；Swift 回执与消息清理回归通过；macOS Debug 无签名构建通过。本机已安装独立组件，真实 WorkBuddy 加载、健康检查以及置顶会话读取权限检查通过。实际消息发送和灵动岛输入框的完整界面操作尚未完成实测，不能将接口联调等同于真实消息送达。
